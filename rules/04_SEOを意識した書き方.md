# SEOを意識した書き方

サービスサイトの文面を書くときの、検索を意識した言葉の置き方。

**このページは公開ガイドラインの引用ではなく、実際のサービスサイトから読み取った共通点をまとめたもの。**
根拠になった文面は [11 機能紹介](sections/11_機能紹介.md)、[10 導入事例](sections/10_導入事例.md) に載せている。

---

## 大原則：見出しは検索語、説明文で価値

| 場所 | 何を置くか |
|---|---|
| 見出し（h1・h2・機能名） | 検索されている一般名詞をそのまま |
| 説明文 | 検索語を繰り返さず、価値と変化を書く |

SmartHRの機能一覧は、機能名がすべて「給与計算」「勤怠管理」「年末調整」という一般名詞で、
独自の名前を付けていない。説明文のほうで差をつけている。

- ❌ 見出し「スマート給与エンジン」／説明「給与計算がラクになります」
- ⭕️ 見出し「給与計算」／説明「データ入力レス×チェック作業スリム化で、不安のない給与計算へ」

**見出しで独自性を出そうとすると、検索でも読み手でも負ける。**

---

## 1. 検索語を言い換えない

社内で使っている呼び方より、**顧客が検索する言葉**を優先する。

| 社内語・造語 | 検索される言葉 |
|---|---|
| タレントマネジメント基盤 | 人事評価／スキル管理 |
| ワークフローエンジン | 申請・承認 |
| コンテンツサプライ | 記事制作代行 |
| Webグロース支援 | サイト改善／SEO対策 |

造語をどうしても使いたいときは、**一般名詞と併記する**。

- ⭕️ キャリア台帳（Talent Canvas）

---

## 2. 同じ語を繰り返さない

見出しに1回入れたら、説明文では言い換える。同じ語を並べても順位は上がらず、読みにくくなる。

- ❌ 勤怠管理システムなら勤怠管理がカンタンな勤怠管理ツール
- ⭕️ 見出し「勤怠管理」／説明「労務担当者も従業員もカンタン操作、残業削減へ」

---

## 3. 見出しは名詞、説明は文にする

見出しを文にすると、検索語が埋もれる。

| ❌ 見出し | ⭕️ 見出し |
|---|---|
| 給与計算がラクになります | 給与計算 |
| 年末調整でお困りではありませんか？ | 年末調整 |
| BtoBサイト制作で成果を出す方法 | BtoBサイト制作 |

疑問形の見出しは、記事なら機能するが、**サービスページでは使わない**。

---

## 4. 属性のメタ情報を必ず添える

導入事例・実績には、業種と規模を添える。読み手が自分に近い事例を選べるだけでなく、
一覧の絞り込みや内部リンクの土台になる。

> 転記作業を削減し、業務量を7割削減
> ——有限会社上手工作所（製造業・メーカー、51〜100名）

| 添える属性 | 例 |
|---|---|
| 業種 | 製造業・メーカー／医療・福祉施設業／不動産・建築・建設業 |
| 規模 | 21〜50名／301〜500名／全国150事業所 |
| 地域 | 北海道の管工事・冷設会社 |
| 導入時期 | 2024年導入 |

---

## 5. タイトルは「変化 ＋ 条件」で作る

数字だけ、キーワードだけのタイトルは読まれない。

```
（作業）を（前）から（後）へ。（条件・制約）でも（成果）
```

> 全国150事業所の年末調整が1か月から9日へ。社用端末なしの現場にも9割浸透

前半で検索語と数字を、後半で「自分にも当てはまるか」を判断させている。

---

## 6. 記事とサービスページで書き分ける

同じ検索語を狙っても、面によって書き方が違う。

| | サービスページ | 記事・コラム |
|---|---|---|
| 見出し | 名詞（勤怠管理） | 文・疑問形（勤怠管理を効率化する5つの方法） |
| 主語 | 自社サービス | 一般論・読者 |
| 目的 | 選んでもらう | 理解してもらう |
| 数字 | 自社の実績 | 出典のあるデータ |
| CTA | 資料請求・問い合わせ | 関連記事・サービスページ |

**サービスページに記事の書き方を持ち込むと、売り物が何か分からなくなる。** 逆も同じ。

---

## 7. やらないこと

| ❌ | なぜ |
|---|---|
| 見出しにキーワードを3語詰め込む | 読みにくく、評価も上がらない |
| 「〜とは」をサービスページの見出しにする | 記事の型。サービスページの検索意図とずれる |
| 検索語を本文に不自然に混ぜる | 日本語として破綻する |
| 独自の造語だけで機能名を作る | 検索されない |
| 業種・規模を書かない導入事例 | 読み手が自分に当てはめられない |
| 「業界No.1」を注記なしで書く | 根拠がなく、景品表示法の観点でも危うい |

## サービスサイト全体のSEO戦略

言葉の置き方だけでなく、**ページの分け方**にも共通のやり方がある。SmartHRとfreeeの構成から読み取れるもの。

### 1. 機能ページを検索語ごとに分ける

SmartHRは「給与計算」「勤怠管理」「年末調整」「人事評価」を、それぞれ独立した機能名として立てている。
1ページに全機能を詰めると、どの検索語でも中途半端になる。**1ページ1検索語**が基本。

上位のカテゴリ（労務管理／タレントマネジメント／従業員ポータル）で束ねることで、
上位概念の検索語も押さえつつ、個別の検索語ページに流している。

### 2. 導入事例を、属性つきの資産にする

freeeは全事例に業種と従業員数レンジを併記している。これは読み手のためであると同時に、

| 属性 | 効くこと |
|---|---|
| 業種 | 「製造業 勤怠管理」「介護 労務管理」といった検索に、事例ページが応える |
| 規模 | 「中小企業向け」「従業員数1000名」などの検索意図に合致する |
| 機能名 | 事例タイトルに機能名を入れると、機能ページへの内部リンクが自然になる |

**事例は書けば書くだけ資産になる、数少ないコンテンツ。** 属性を決めずに書き始めると、後から整理できなくなる。

### 3. 事例タイトルにロングテールを仕込む

> 全国150事業所の年末調整が1か月から9日へ。社用端末なしの現場にも9割浸透

「年末調整」という主要語に加えて、「150事業所」「社用端末なし」という具体条件が入っている。
狙って書かなくても、**具体的に書けば自然とロングテールになる。** 逆に「業務効率化を実現」では何にも当たらない。

### 4. 料金・FAQで指名検索の周辺語を取る

サービス名で検索する人は、たいてい「サービス名 + 料金」「+ 評判」「+ 解約」「+ 使い方」と続けて調べる。
このうち自社で答えられるもの（料金・解約・導入の流れ）は、**必ず自社サイトに置く**。
置かないと、比較メディアやまとめサイトが代わりに答えることになる。
