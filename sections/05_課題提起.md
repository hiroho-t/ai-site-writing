# 課題提起

サービスページやLPの冒頭で、読み手の状況を言語化するセクション。
**恐怖で動かさない。** 状況を記述して、読み手に判断させる。

---

## このセクションに書くこと

| 要素 | 必須 | 中身 |
|---|---|---|
| 状況の記述 | ◎ | 誰が・何をしていて・何が起きているか |
| 根拠 | ○ | 自社調査の数字、公開データ。出どころを書く |
| 原因 | ◎ | なぜそうなるのか |
| 接続 | ◎ | だから本サービスがある、という橋渡し |

---

## 型

```
状況の記述（誰が・何をしていて・何が起きているか）
 → その原因
 → だから本サービスがある
```

数字を使う場合は、**出どころを必ず書く**。出どころのない数字は煽りになる。

---

## 事例

### ウィルゲート（[SEOサービス](https://www.willgate.co.jp/seo/)）

> SEO対策に取り組む（または検討している）9割を超えるWeb担当者が何らかの課題を抱えていることが明らかになりました。

**効いている点**
- 自社調査の数字を根拠にしている。「〜が明らかになりました」で、調査結果であることを示している。
- 「取り組む（または検討している）」と対象を括弧で補足していて、読み手が自分に当てはまるか判断できる。

### ベイジ（[サービス](https://baigie.me/service/)）

> 机上の空論や単なる表層的なロゴなどの制作ではなく、BtoB企業ならではの経営に影響を与える現実的なブランディングをご提案します。

**効いている点**：業界にありがちなやり方を否定してから、自社のやり方を出している。**読み手を責めずに、業界の慣行を問題にしている**のがポイント。

### ベイジ 採用（[採用](https://baigie.me/recruit/)）

> 母集団形成／歩留まり改善／内定辞退回避

**効いている点**：課題を煽り文ではなく、**工程の用語で並べている**。担当者は自分がどの工程で困っているかを選べる。

---

## 使える言い回し

| 場面 | 表現 |
|---|---|
| 状況を述べる | 次のような状況で、ご相談をいただくことが多くあります |
| 調査を根拠にする | 〜という結果になりました／〜であることが明らかになりました |
| 原因を示す | 〜に時間がかかる原因は、△△にあります |
| 影響を示す | 対応が遅れると、□□の影響が出ます |
| 業界慣行を否定する | 〜ではなく、〜をご提案します |
| 工程で分ける | 母集団形成／歩留まり改善／内定辞退回避 のように工程名で並べる |

---

## やらないこと

| ❌ | なぜ | ⭕️ |
|---|---|---|
| こんなお悩みはありませんか？＋抽象的な悩み | 定型句そのものは可。**直後が抽象的だと死ぬ** | こんなお悩みありませんか？＋「観光マップはあるけど活用されていない」のように具体的な状況を3つ |
| もう◯◯で悩むのはやめませんか？ | 呼びかけが押し付けがましい | ◯◯に時間がかかる原因は、△△にあります |
| このままでは手遅れになります | 恐怖で動かしている | 対応が遅れると、□□の影響が出ます |
| 9割の企業が失敗しています | 出どころがない | 自社調査（2026年◯月、n=◯）では、〜という結果でした |
| ほとんどの担当者が間違えています | 読み手を責めている | 対応が漏れやすい箇所です |
