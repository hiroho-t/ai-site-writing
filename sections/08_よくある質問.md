# よくある質問

FAQページ。**できないことは、できないと先に書く。** 濁すと不信になる。

---

## このセクションに書くこと

| 要素 | 必須 | 中身 |
|---|---|---|
| 質問文 | ◎ | 顧客の言葉のまま。社内用語に翻訳しない |
| 結論 | ◎ | 回答の1文目に置く。「はい、可能です」「できません」 |
| 条件・例外 | ◎ | どこまでできて、どこからできないか |
| 相手にお願いすること | ○ | 発注側の作業を明示する |
| 次の行き先 | ○ | 詳細ページ、問い合わせ先 |

---

## 型

```
Q：顧客の言葉のまま
A：結論（1文目）→ 条件・例外 → 相手にお願いすること
```

---

## 事例

### ベイジ（[よくある質問](https://baigie.me/faq/)）

> **Q. コピーを書いてもらうことはできますか?**
> はい、可能です。ただしその場合も、私たちがお客さまのことに精通していることはほとんどないので、コピーの元になる一次情報はご提供いただくことになります。

> **Q. コピーを発注側で用意する場合でも、リライトなどは対応してもらえますか?**
> はい、行います。また、ご準備いただいた原稿の質が低く、ウェブ戦略として機能しないレベルの場合、そのことをお伝えした上でテコ入れすることもあります。

> **Q. 元情報やコピーの提供に時間がかかりそうですが、どうなりますか?**
> 元情報やコピーの提供が遅れると、そのままスケジュールに影響を与えることが多いです。

> **Q. サーバ環境も変えたいのですが、お願いすることは可能ですか?**
> サーバー会社のご提案自体は可能です。ただし、サーバー会社との契約自体はお客さまに行っていただくことになります。

> **Q. ブラウザチェックが、最終確認より後なのはなぜですか?**
> ブラウザチェック後に、追加要望が出て手を加えると、新たなエラーや不具合が発生しても検知できないためです。

> **Q. 運用のレクチャーをしていただけますか?**
> はい、必ずします。公開後1週間をめどに、CMSのオペレーションをレクチャーします。

**効いている点**
- 全問が「はい、可能です」「はい、行います」と**結論から始まる**。読み手は1行目で判断できる。
- 「ただし」で条件を必ず添える。できることとできないことの境界が明確。
- **「原稿の質が低く」「遅れると、そのままスケジュールに影響を与える」と、言いにくいことを書いている。** FAQで信頼が生まれるのはここ。
- 「〜なのはなぜですか?」という**理由を聞く質問に、理由で答えている**。工程の設計意図を説明することで、専門性が伝わる。
- 期間を数字で書いている（1週間ほど、公開後1〜3カ月、公開後1週間をめど）。

## 使える言い回し

| 場面 | 表現 |
|---|---|
| できる | はい、可能です／はい、行います／はい、必ずします |
| 条件を付ける | ただしその場合も、〜いただくことになります |
| 相手の作業を示す | 〜は、お客さまに行っていただくことになります |
| できない | 現在は対応していません。◯◯であれば対応できます |
| ケースバイケース | 内容次第でケースバイケースですが、可能な範囲で対応します |
| 期間を示す | 通常、1週間ほどになります／公開後1〜3カ月を目安に |
| 理由を説明する | 〜すると、〜が発生しても検知できないためです |
| 制約を先に伝える | 〜が遅れると、そのままスケジュールに影響を与えることが多いです |

## やらないこと

| ❌ | なぜ | ⭕️ |
|---|---|---|
| 解約につきましては、原則として所定の手続きが必要となっておりますので、詳しくは担当者までお問い合わせください | 結論がない | できます。契約は月単位で、ご連絡をいただいた月の末日までご利用いただけます |
| 対応いたしかねる場合がございます | 濁している | 現在は対応していません。◯◯であれば対応できます |
| お客様のご要望に応じて柔軟に対応いたします | 何ができるか不明 | ◯◯と△△は対応できます。□□は対応していません |
| 詳しくはお問い合わせください（だけ） | たらい回し | 判断に必要な情報をここに書き、そのうえでリンクを添える |
